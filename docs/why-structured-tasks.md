# Why structured tasks

Autonomous coding turns prose into edits, checks, and a completion claim. When
scope, decisions, or proof are unclear, the same request can produce drift,
unrelated changes, or a confident but wrong report.

Task-format treats that problem as an experiment. A package makes the outcome,
boundaries, fixed choices, and acceptance evidence explicit. A fresh run limits
hidden state. An independent gate checks the result after the agent stops.

This matters in the AI world because speed magnifies ambiguity: an agent can
modify a repository faster than a human can notice that it chose the wrong
boundary. Structured inputs make the intended boundary inspectable and
machine-checkable.

The project does not claim one universal prompt, rank models, or replace
engineering judgment. It tests specific task-writing choices and keeps only
changes supported by repeated evidence.
